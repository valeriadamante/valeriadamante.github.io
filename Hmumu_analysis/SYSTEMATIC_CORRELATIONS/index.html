    Correlations of the systematics across eras¶

    The properties are read from config/Run3_<era>/systematics.yaml in the same block that contains name. They work for systematics, weights, derived_systematics and qcd_scale (with overrides in the individual variations). The nuisance name is resolved by common/systematic_correlations.py.

    # One nuisance common to all eras
isCorrelated: true
Eras_correlated: all

# One independent nuisance for each physical era (2022 and 2022EE included)
isCorrelated: false

# One nuisance common only to these sub-eras; the others stay independent
isCorrelated: true
Eras_correlated: [2022, 2022EE]

# Two independent groups, each correlated internally
isCorrelated: true
Eras_correlated: [[2022, 2022EE], [2023, 2023BPix]]

    Configure the corresponding blocks consistently in the eras involved. Names with or without Run3_ are accepted, and YAML years as numbers or strings. With isCorrelated: false, Eras_correlated is ignored. With true and without Eras_correlated, all is assumed. If both fields are absent, the previous convention remains, determined by the {era} placeholder in the name. Empty groups, overlapping groups or groups with duplicates are rejected.

    Example with name: CMS_example_{era}:

    Configuration Era Nuisance name
    false 2022EE CMS_example_2022EE
    true, all any CMS_example
    true, [2022, 2022EE] 2022 or 2022EE CMS_example_2022_2022EE
    true, [2022, 2022EE] 2023 CMS_example_2023

    If the name does not contain {era}, the necessary suffix is added. The names of the skim columns do not change: what changes is the name of the nuisance in the ROOT templates and therefore in the datacards. The builders that discover the Up/Down pairs from the histograms inherit these correlations automatically.

    JES: “simple” model of the provided table¶

    The JetMET regrouped sources already available in the skims are used, not JES Total together with the sources. The configuration covers all seven eras 2022–2026.

    Regrouped nuisance Sources of the table Across years
    Absolute AbsoluteMPFBias, AbsoluteScale, Fragmentation, PileUpDataMC, PileUpPtRef, RelativeFSR, SinglePionECAL, SinglePionHCAL 100%
    BBEC1 PileUpPtBB, PileUpPtEC1, RelativePtBB 100%
    EC2 PileUpPtEC2 100%
    HF PileUpPtHF, RelativeJERHF, RelativePtHF 100%
    FlavorQCD FlavorQCD 100%
    RelativeBal RelativeBal 100%
    Absolute_year AbsoluteStat, RelativeStatFSR, TimePtEta independent
    BBEC1_year RelativeJEREC1, RelativePtEC1, RelativeStatEC independent
    EC2_year RelativeJEREC2, RelativePtEC2 independent
    HF_year RelativeStatHF independent
    RelativeSample_year RelativeSample independent

    The sources that are independent across years are correlated between 2022/2022EE and between 2023/2023BPix. 2024, 2025 and 2026 each have a distinct nuisance. This is an application of the “simple” column of the user's table; it does not implement the partial coefficients of the “realistic” model. The other systematics keep the previous policy, now explicit: JER, muons, PU and EWK PS separate per era; QCD/PDF correlated across eras according to their process labels.

    Production, merge and plots¶

    The DNN/all_variables campaigns use --jes regrouped by default, with 11 JES families produced separately. The families with the _year suffix are translated into the skim source of the current era: for example JESRegrouped_Absolute_year → JESRegrouped_Absolute_2022EE. --jes total selects the previous JES Total model. Keep the same option in submit/check/hadd/merge/plot. The plot refuses the double counting of Total and regrouped when both are present.

    ./hmumu hist dnn_vbf submit --mode both --eras 2022,2022EE,2023,2023BPix --jes regrouped
# After the jobs:
./hmumu hist dnn_vbf finish --mode both --eras 2022,2022EE,2023,2023BPix --jes regrouped
./hmumu hist dnn_vbf check --mode both --stage all --eras 2022,2022EE,2023,2023BPix --jes regrouped

    For a single component: --families JESRegrouped_Absolute_year --mode syst. For all_variables replace the campaign name; for a different JES model use a dedicated --output-dir.

    The era merge builds templates with the total yield, varying only the eras affected by the nuisance. Example: nominals 10 and 20, variation +2 in the first era → combined nominal 30, varied template 32 (not 12). For inputs containing only variations, the direct command requires Central:

    ./hmumu merge-eras /production/PU_hadded \
  --nominal-dir /production/Central_hadded \
  --eras 2022,2022EE --output-era 2022_2022EE --run

    The campaigns pass --nominal-dir automatically. Writes are atomic per file. The plots resolve the names from the same configuration, sum the correlated variations and combine the independent nuisances in quadrature.

    After a change of the correlations, regenerate the affected templates (submit --force, or a new output directory), then hadd and merge. Only renaming the files or only redoing the plots does not apply the new policy. Old merges not completed with the nominals must be rebuilt; the campaign receipts have a new version and do not certify the old merges.
