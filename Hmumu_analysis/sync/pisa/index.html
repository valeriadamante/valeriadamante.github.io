    Analysis synchronization¶

    Synchronization is the validation step used to establish that two independent analysis implementations select the same events, reconstruct the same physics objects and apply compatible event weights. The workflow below is general and can be reused for every external or internal comparison.

    Scope and goals¶

    A synchronization should separate differences in the input sample from differences introduced by selections, object definitions, corrections or event weights. The comparison is complete when every relevant discrepancy is either removed or understood and documented.

    Prerequisites¶

    • the exact same NanoAOD files and, for data, the same certified luminosity mask;
    • a shared definition of triggers, physics objects, overlap removal and event selections;
    • a common convention for systematic variations, normalization and event weights;
    • event identifiers (run:luminosityBlock:event), cutflows and the main object-level variables in the output;
    • the software versions, configuration tags and commands needed to reproduce both productions.

    Recommended validation order¶

    1. confirm the number of input files and processed events;
    2. compare unweighted cutflows one selection at a time;
    3. match accepted events and inspect the first divergent selection for exclusive events;
    4. compare the multiplicity and kinematics of muons, electrons and jets;
    5. for simulation, validate generator and correction weights individually before the total weight;
    6. compare final categories, distributions and weighted yields.

    Required output¶

    Each campaign should retain the input-file list, configuration or production tag, commands, cutflow tables, lists of common and exclusive events, comparison plots and a short explanation of every residual difference. Percent agreement alone is not sufficient: the origin and physics impact of the remaining differences must be recorded.

    Current case study: Pisa¶

    The TAMU and Pisa analyses were compared event by event for Run2024H data and for the 2024 VBFH simulated signal sample. The following sections document the concrete setup and results.

    Synchronization procedure¶

    The comparison uses the same NanoAOD inputs on both sides and proceeds in four steps:

    1. agree on the exact input files, event selection, mass region and object definitions;
    2. produce the TAMU synchronization tuples and cutflow tables;
    3. match events on run:luminosityBlock:event and identify the first failed selection step for events accepted by only one analysis;
    4. compare object kinematics and, for simulation, each common weight factor before comparing the total weighted yield.

    For the Pisa-compatible Run2024H production:

    ./hmumu sync special_sync_submit --variant filippo_20260925
./hmumu sync special_sync_merge --tag filippo_20260925
./hmumu sync compare_filippo_diagnostic --tag filippo_20260925 \
  --output-dir "$HMUMU_SYNC/confronto_filippo_20260925"
./hmumu sync plot_filippo_comparison --tag filippo_20260925 \
  --output-dir "$HMUMU_WWW/skim_v4/studies/sync/filippo_20260925"

    The data comparison is unweighted. For simulation, the validation is performed first with the generator weight and then with pile-up, muon identification and isolation, and trigger scale factors included.

    Run2024H data¶

    selection result Muon0 Muon1 total
    TAMU 11,050 11,108 22,158

    The common sample contains 99.8% of the events selected by Pisa. The total yields differ by 0.6%, with 219 events differing in the union.

    identified cause TAMU only Pisa only
    jet veto-map treatment in the b-jet veto 98 0

    veto-map treatment of the VBF jets 15 0
    electrons with 10–15 GeV 0 7
    FSR photon treatment 12 3
    not yet explained 6 2

    The kinematic ratios remain within 1–2% over most of the distributions. The largest visible structure is a 2–3% difference around $|\eta(j_2)|=2.0$–2.5, associated with the different 2024 JEC treatment.

    VBFH 2024 simulation¶

    Both analyses use the same 190 NanoAOD files, corresponding to 11.19 million generated events.

    selection result events
    TAMU 2,294,633
    Pisa 2,284,560
    common 2,257,365
    TAMU only 37,268
    Pisa only 27,195

    The shared sample is 98.4% of the TAMU selection and 98.8% of the Pisa selection. The dominant residual difference is associated with migrations near the jet transverse-momentum and dijet-mass thresholds.

    Event weights¶

    factor summed TAMU/Pisa ratio result
    generator weight 1.0000 identical event by event
    pile-up 1.0000 identical event by event
    muon identification and isolation 0.9899 different scale factors
    trigger 0.9910 different scale factors
    complete event weight 0.9809 difference driven by muon scale factors

    The expected VBF signal-region yields are 19.94 versus 19.85 with generator weights only, and 19.23 versus 19.51 with all common weights. Thus TAMU/Pisa is +0.4% before scale factors and −1.4% after all common weights.
