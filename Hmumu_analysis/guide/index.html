    Framework guide: from NanoAOD to combine¶

    Updated 2026-10-06. One guide for the whole analysis, in the order the steps are run: setup, skims, validation, DY weights, histograms, plots, datacards and fits, with one recipe per case. Every command can be copied as it is, from the repository root, after source env.sh.

    The Italian version is guida.md; the two have the same sections. Results are not in this guide: they are in status.md (all the studies), combine/RESULTS.md (DNN fit) and combine/results_fit_matrix/SUMMARY.md (fit matrix). Reference pages: systematic correlations, why the EWK Z fit, DY reweighting method, corrections and payloads, code layout and tests.

    Templates to use (2026-10-06). The dnn_vbf_weighted templates (hmumu hist dnn_vbf) do not re-evaluate the DNN for JES, JER and the muon scale/resolution: their jet and muon systematics are wrong, and so is every DNN fit made with them. Use dnn_vbf_eta_regions_syst with --eta-categories incl (section 7).

    1. Overview¶

    NanoAOD ──skim──> skims ──validate──> manifests ──dy-weights──> DY payloads
        ──hist──> histograms ──hadd──> per process ──merge-syst──> templates (Hists_systMerged)
        ──plot──> Data/MC, systematic shapes
        ──combine──> datacards ──fit_suite / run_fit_matrix──> r, significance, pulls, impacts, scans, pre/post-fit

    One command line, ./hmumu <stage> <action>, runs every stage; each prints what it runs, --dry-run shows the plan without doing anything, --help works everywhere (./hmumu hist dnn_vbf --help).

    stage command output (keys of config/paths.yaml)
    file lists ./hmumu skim files config/<era>/samples_withfiles.yaml
    skims ./hmumu skim submit\|check $HMUMU_SKIM/<era>/<dataset>/skim_N.root
    manifests ./hmumu validate $HMUMU_MANIFESTS/<era>/<dataset>.json
    DY weights ./hmumu dy-weights run reweights/dy_*_reweight_skim_v4/<era>/*.json
    histograms ./hmumu hist <campaign> submit\|hadd\|merge-syst $HMUMU_HISTOGRAMS/<campaign>/...
    checks python3 tools/check_templates.py –
    plots ./hmumu hist <campaign> plot, ./hmumu plot, plot_systematics_campaign.py $HMUMU_WWW/...
    datacards ./hmumu combine cards, build_signal_extended_datacards.py, fit_ewkz_systematics.py combine/results_*/
    fits ./hmumu combine fit, combine/fit_suite.py, combine/run_fit_matrix.sh combine/results_*/
    everything after the skims ./hmumu chain all –
    what is missing ./hmumu status –

    The analysis is the VBF H→μμ search in Run 3, seven eras: 2022, 2022EE, 2023, 2023BPix, 2024, 2025, 2026. The fit variable is the output of the VBF DNN (DNN_NNOutput) in the VBF category. Mass regions (config/<era>/selections.yaml):

    region m(μμ) [GeV] fit plots
    Signal_Fit (SR) 115–135 yes, blinded above DNN 0.8 yes, blinded
    H_sideband 110–115, 135–150 yes yes
    Signal_ext 110–150 = Signal_Fit + H_sideband no (it would double count) yes
    Z_sideband 70–110 control region, post-fit plots of the data fit yes
    mass_inclusive 60–150 no yes

    Templates with systematics are needed in every region: the fit reads only its channels, the plots show the pre-fit systematic bands everywhere and the post-fit in the control regions. Since the routing (6.5) fills Signal_ext and mass_inclusive with the inclusive DY/EWK samples, Signal_ext with the 105–160 samples is obtained by adding Signal_Fit and H_sideband. A second classifier, the VBF selector (VBFSel_NNOutput), is used to measure the EWK Z (VBF Z) normalisation in the sidebands.

    2. Setup¶

    git clone git@github.com:valeriadamante/Hmumu_analysis.git
cd Hmumu_analysis
source env.sh                                    # bash or zsh
voms-proxy-init --voms cms --valid 192:00 --out data/voms.proxy
./hmumu doctor                                   # checks the setup
./hmumu paths                                    # where data are read and written

    env.sh:

    • creates a CMSSW area in soft/ the first time (CMSSW_15_0_2; source env.sh --cmssw-version CMSSW_15_3_0 for another one) and loads it: ROOT, correctionlib, uproot, the python packages;
    • sets ANALYSIS_PATH and PYTHONPATH to the checkout and changes directory into it (cd elsewhere only after sourcing);
    • defines run_combine_tool, combine, combine_cards: combine v11 from the CVMFS container, no local build (COMBINE_IMAGE selects another image);
    • exports the storage locations as HMUMU_<KEY>.

    Arguments of a script that sources it are ignored, so source env.sh is safe inside other scripts. The grid proxy is needed for the skims (xrootd) and is forwarded to every Condor job; X509_USER_PROXY, when set, wins over data/voms.proxy.

    Storage locations¶

    Every path outside the repository is a key of config/paths.yaml:

    key content
    skim skims, <skim>/<era>/<dataset>/skim_N.root + report_N.json
    skim_no_horn_veto 2025/2026 skims without the jet horn veto
    manifests validation manifests
    dy_weight_histograms inputs of the DY-weight fits (jet/, ptll/, njets/)
    histograms every histogram campaign
    sync synchronisation exchange area
    www web area of the plots
    proxy grid proxy for the Condor jobs 
    ./hmumu paths skim                               # one value
export HMUMU_SKIM=/eos/user/j/jdoe/skim_v4       # override one key
export HMUMU_PATHS=~/hmumu_paths.yaml            # or a file with only the keys you change

    Precedence: HMUMU_<KEY>, then HMUMU_PATHS, then config/paths.yaml. Values can refer to other keys ("{eos_user}/manifests_skim_v4") and to the checkout ("{repo}/data/voms.proxy"). In code, paths are read with common.paths.path(key) (Python) or $HMUMU_<KEY> (shell), never written out.

    Per-era configuration¶

    Eras are not copies of each other (the categories: block differs between 2022–2023 and 2024–2026): always read the file of the era you work on.

    file content
    config/<era>/maincfg.yaml luminosity, golden JSON, corrections, histogram variables
    config/<era>/samples.yaml datasets, NanoAOD paths, additional_cuts
    config/<era>/samples_withfiles.yaml resolved file lists (generated, not in git)
    config/<era>/process_names.yaml datasets → processes, DY-weight payloads (reweight_jsons), split_jet_components
    config/<era>/selections.yaml objects, mass regions, categories (store: True = produced by --regions all)
    config/<era>/systematics.yaml variations, nuisance names, cross-era correlation
    config/<era>/skim_cfg.yaml processes to skim, chunking
    config/plot/histograms.yaml binning, blinding (blind_range)
    config/histogram_sample_routing.yaml which DY/EWK sample fills which mass region
    config/crossSections13p6TeV.yaml cross sections and their uncertainties
    config/campaigns/*.sh histogram campaigns (section 6)

    3. Skims¶

    The skim reads NanoAOD, applies object selection and corrections (analysis/, corrections/) and stores corrected objects and the nominal and shifted primitives. Categories are defined later, at histogram level, so they can change without re-skimming as long as the primitives are stored.

    3.1 File lists¶

    ./hmumu skim files --era Run3_2024 --use-ext     # one era per call; --use-ext adds the extensions
# moving to newer NanoAOD versions first:
python3 htcondor/update_nanoaod_versions.py --era Run3_2024,Run3_2025 --include-data --dry-run
python3 htcondor/update_nanoaod_versions.py --era Run3_2024,Run3_2025 --include-data --in-place
git diff config/Run3_*/samples.yaml

    3.2 Submit¶

    ./hmumu skim plan    --era 2024                     # the submitter commands
./hmumu skim dry-run --era 2024                     # missing chunks, nothing submitted
./hmumu skim submit  --era 2024 --max-submit-jobs 1 # one test job
./hmumu skim submit  --era 2024                     # the whole era
./hmumu skim submit  --era 2025 --dataset VBFHto2Mu_M125_powheg_herwig   # one dataset

    Without --era all seven eras are selected. Only chunks without output are submitted, so submit also resumes; to redo a chunk delete its skim_N.root and report_N.json.

    option effect
    --dataset NAME one dataset (repeatable)
    --variant with\|without\|both 2025/2026: with/without the jet horn veto (default both)
    --n-events N test, N events per job, to <skim>_testN
    --output PATH another skim base
    --max-submit-jobs N, --max-parallel-jobs N throttling
    HMUMU_MAX_QUEUED_JOBS (env, default 3000) global cap: idle + running jobs of the user, all campaigns; a cluster materialises at most this many jobs and is submitted only when the queue has room
    --proxy PATH proxy to forward

    Chunks: at most 5 GB and 5 files per job (target_chunk_size_gb, max_files_per_chunk in skim_cfg.yaml); the chunk → files map and the job logs are in htcondor/<skim name>/<era>/<dataset>/.

    3.3 Check¶

    A job killed after the Snapshot leaves a full .root without its report; a truncated file opens but has fewer events than its report. skim check opens every chunk, reads the last event and compares with the report:

    ./hmumu skim check --era 2024 --output results/skim_v4/check_Run3_2024.json
./hmumu skim check --era 2025 --no-horn-veto
python3 analysis/check_duplicate_mc.py skim_0.root [skim_1.root]   # duplicated events

    Empty datasets (no events in any file) break tools that read the skims directly; to list them:

    cd "$HMUMU_SKIM" && for era in */; do for d in "$era"*/; do
  ls -l "$d"*.root 2>/dev/null | awk -v d="$d" '$5>10000{ok=1} END{if(!ok) print "EMPTY", d}'
done; done

    4. Validation manifests¶

    Histogram jobs read one manifest per dataset: the valid skim_N.root/report_N.json pairs and the normalisation of the whole dataset (so a job on a subset of files is still normalised correctly).

    ./hmumu validate --eras 2024                    # every skimmed dataset, on Condor
./hmumu validate --eras 2022,2022EE --dry-run
./hmumu validate --eras 2025 --no-horn-veto
./hmumu validate --eras 2024 --datasets signals,EWK --local

    Only missing manifests are written. A dataset without a manifest is excluded by the campaigns and reported as [UNAVAILABLE]: do not start histograms while manifests are missing.

    5. DY weights¶

    Three data-driven DY corrections, fitted in the Z sideband in a fixed order, each on top of the previous one:

    stage campaign payload
    jet: normalisation of the jet components (0J, 1J Hard/PU, 2J Hard/PU1/PU2, VBF Hard/PU) dy012j_skim_v4 reweights/dy_012j_reweight_skim_v4/<era>/dy_012j_reweight.json
    ptll: pT(μμ) shape per jet category dy_ptll_skim_v4 reweights/dy_ptll_reweight_skim_v4/<era>/dy_ptll_reweight_smart.json
    njets: selected-jet multiplicity, ggF and VBF dy_njets_skim_v4 reweights/dy_njets_reweight_skim_v4/<era>/dy_njets_reweight.json

    The payloads used are the reweight_jsons of the DY process in config/<era>/process_names.yaml, one per era. The method is in sync/dy_reweighting.md.

    ./hmumu dy-weights run --eras 2022,2022EE,2023,2023BPix,2024,2025,2026

    run does one step and returns: it submits the first incomplete stage, or hadds and fits it when its histograms are there. Exit code 3 = submitted, waiting for Condor (not an error); 0 = all three payloads up to date. Call it again after each wave, or let ./hmumu chain dy-weights wait. A payload older than its input histograms is refitted.

    Step by step:

    ./hmumu dy-weights check         --weight-stage jet --eras 2024
./hmumu dy-weights submit        --weight-stage jet --eras 2024
./hmumu dy-weights hadd          --weight-stage jet --eras 2024
./hmumu dy-weights fit           --weight-stage jet --eras 2024 [--fit-option --pu1-pu2=tied]
./hmumu dy-weights check-weights --weight-stage jet --eras 2024

    The fits write their diagnostic plots next to the payloads (dy_012j_{0J,1J,2J,VBF}_{pre,post}fit.png, {ggF_0J,...}_ptll_*.png, {ggF,VBF}_njets_*.png). The tools are tools/derive_dy_012j_reweight.py, tools/derive_dy_ptll_njets_reweight.py, tools/derive_dy_njets_reweight.py.

    A refit invalidates every DY histogram of that era: the checks mark them STALE and hadd stops. Reproduce them:

    ./hmumu hist all_variables submit --mode central --eras 2025 --datasets region_auto --force

    Campaigns apply the three weights by default. To choose: --dy-weights jet-component,ptll (two of them), --dy-weights '' (none). Only DY datasets read the payloads.

    6. Histograms¶

    histograms/hist_maker.py fills histograms from the skims of one dataset; a campaign runs it on Condor for every dataset, era and systematic family, then aggregates. Engine: campaigns/workflow.py; every action checks its inputs and outputs and stops (exit 1) on anything incomplete.

    ./hmumu hist <campaign> <action> [options]
./hmumu hist <campaign> paths          # resolved inputs, output, eras, families, options

    6.1 Campaigns¶

    One file per campaign in config/campaigns/ (CAMPAIGN_ROOT, ERAS, SYSTEMATICS, DATASETS, HIST_ARGS, job size; see the README).

    campaign content systematics use
    dnn_vbf_eta_regions_syst DNN, VBF, Z/Signal_Fit/H sideband, incl/CC/CF/FF, DY/EWK jet components all DNN fit input
    dnn_vbf (root dnn_vbf/ since 2026-10-06) DNN, VBF, five regions, components all DNN plots in every region (Signal_ext, mass_inclusive too)
    dnn_vbf_weighted (old root of dnn_vbf) the same, produced 2026-09-17 all, JES/JER/ScaRe wrong (below) to be deleted
    dnn_vbf_dy_unweighted as dnn_vbf without DY weights Central DNN study
    all_variables every stored region/category × every maincfg variable all Data/MC
    vbf_eta_regions all variables, VBF split incl/CC/CF/FF Central η study
    dnn_vbf_eta_regions DNN, VBF split incl/CC/CF/FF Central η study
    vbf_selector_ewkz VBF-selector score and its 24 inputs, Z and H sidebands, components all EWK Z fit input
    vbf_pair_definition alternative VBF pairs (VBF_PAIR_DEF=maxmjj\|hardest\|leading) Central pair study
    dy012j_skim_v4, dy_ptll_skim_v4, dy_njets_skim_v4 DY-weight inputs Central via hmumu dy-weights
    jet_horn_veto Data/DY with and without the horn veto (built in workflow.py) Central horn-veto study

    6.2 Actions¶

    action does
    paths resolved configuration
    check --stage S histograms, hadded, merged-eras, merged-syst, merged, all
    submit submit missing and broken outputs to Condor
    local the same, here
    validate missing manifests of the campaign's datasets
    hadd dataset files → process files, per era and family (--jobs N)
    merge-syst Central + every family → one file per process (Hists_systMerged/), with a receipt
    merge-era sum of eras into a pseudo-era (--merged-era NAME)
    plot plots per era; --merged for a merged era
    finish hadd → merge-syst → plot (→ merge-era → merged plots)
    option meaning
    --eras 2024,2025 eras (default: the campaign's ERAS)
    --mode central\|syst\|both Central, the families, or both
    --families PU,Muon subset of families
    --jes regrouped\|total 11 regrouped JES sources (default) or the total
    --dy-weights ... DY reweights to apply ('' none)
    --regions, --categories, --variables, --datasets override the selection
    --input-dir, --manifest-root, --output-dir override the bases
    --memory 20GB, --threads 8, --variable-batch-size N job size
    --check-level files presence/size/time only, no ROOT opening (fast)
    --force redo the whole selection
    --missing-only hadd: resume, removing empty/stale/unreadable outputs first
    --dry-run print, do nothing

    6.3 Produce and validate a campaign (the standard sequence)¶

    source env.sh
C=dnn_vbf_eta_regions_syst          # or vbf_selector_ewkz, all_variables, ...
E=2022,2022EE,2023,2023BPix,2024,2025,2026
./hmumu hist $C submit --mode both --eras $E
condor_q -af JobBatchName | sort | uniq -c                         # wait until empty
python3 tools/check_templates.py $HMUMU_HISTOGRAMS/$C --stage raw --quarantine
./hmumu hist $C submit --mode both --eras $E --check-level files   # redo what was quarantined
./hmumu hist $C check --stage histograms --mode both --eras $E --check-level files
./hmumu hist $C hadd --mode both --eras $E
./hmumu hist $C merge-syst --mode both --eras $E
python3 tools/check_templates.py $HMUMU_HISTOGRAMS/$C --stage merged

    Why tools/check_templates.py: check --check-level files does not see a file truncated by an EOS write error, and --check-level root (uproot) can hang on it. The tool opens every file with ROOT (zombie, "recovered", no keys) and, on the merged files, checks that the median of variation/nominal of each template is within 3% of 1 (a hadd that lost a dataset gives about 0.5). --quarantine moves the broken raw files to <campaign>_quarantine_<date>/ (reversible) so submit produces them again. Since 2026-10-06 hist_maker.py fails a job with a truncated output, so Condor retries it.

    When the guarded hadd/merge-syst refuse to run because of datasets that cannot be produced (FlashSim samples in DNN campaigns: their skims lack SoftJetCleanedActivity_*; VBFHto2Mu_M125_powheg_herwig without manifest), run the planned commands directly:

    ./hmumu hist $C hadd --mode both --force --dry-run --check-level files 2>&1 \
  | grep hadd_hists_to_processes.py | sed 's/^\$ //' > hadd_cmds.sh
xargs -a hadd_cmds.sh -d '\n' -P 4 -I{} bash -c '{}'
./hmumu hist $C merge-syst --mode both --force --dry-run 2>&1 \
  | grep merge-systematics | sed 's/^\$ //' | while read -r c; do bash -c "$c --force"; done
python3 tools/check_templates.py $HMUMU_HISTOGRAMS/$C --stage merged

    The direct merge writes no receipt (.workflow_syst_Run3_<era>.json): once check_templates.py --stage merged says OK, build the cards with --allow-unmerged.

    Jobs longer than 8 h (DY M-50 with many variables) are removed by Condor: set +JobFlavour = "tomorrow" in htcondor/<mode>/<dir>/submit.sub and resubmit it, or condor_qedit <cluster> MaxRuntime 86400 while idle. Or shard the dataset:

    ./hmumu shard submit --config all_variables --era 2024 --dataset DYto2Mu_M_50_amcatnloFXFX --shards 10
./hmumu shard merge  --config all_variables --era 2024 --dataset DYto2Mu_M_50_amcatnloFXFX --shards 10

    The shards are normalised with the dataset-wide reports, so their sum equals the unsharded output; merge refuses an incomplete set (--family, --cleanup).

    6.4 Output layout¶

    <root>/<family>/Run3_<era>/<dataset>.root                    per dataset (and per jet component)
<root>/<family>_hadded/Run3_<era>/<process>.root             per process
<root>/Hists_systMerged/Run3_<era>/<process>.root            Central + every family: the datacard input
<root>/Central_hadded/<merged era>/...                       merged eras
<root>/.workflow_syst_Run3_<era>.json                        merge receipt

    Inside a file: <mass region>_<category>/<variable>, shifted templates <variable>_<nuisance>Up/Down. With --vbf-eta-regions one more level: Signal_Fit_VBF/{incl,CC,CF,FF}/DNN_NNOutput. Jet components are separate files: <process>_2J_Hard.root, _2J_PU1, _2J_PU2 (and 0J, 1J_Hard, 1J_PU).

    6.5 Physics options of the producer¶

    • Sample routing (config/histogram_sample_routing.yaml): in Signal_Fit and H_sideband DY and EWK come from the MLL 105–160 samples, elsewhere from the inclusive ones. In 2024–2026 the 105–160 DY is the inclusive sample with GenVBFFilter==0 plus the VBF-filtered one with GenVBFFilter==1 (additional_cuts of samples.yaml). Signal_ext therefore has no DY/EWK templates and is not used in the fit.
    • Jet components (--pu-hard-jet-components): MC split by how many of the two leading jets are matched to a generator jet: 0J, 1J_Hard, 1J_PU, 2J_Hard, 2J_PU1, 2J_PU2. Processes split: split_jet_components of process_names.yaml.
    • VBF η regions (--vbf-eta-regions): incl, CC (both VBF jets |η| < 2.5), CF (one), FF (none). Can be combined with the jet components (fixed in hist_maker.py on 2026-10-06: before, data and non-split MC got no η split).
    • Systematic families: SYSTEMATICS of the campaign; JES as 11 regrouped sources by default; names and correlations in config/<era>/systematics.yaml (SYSTEMATIC_CORRELATIONS.md). The JES, JER and ScaRe families re-select the events and re-evaluate the DNN and the VBF selector (common/dnn_application.ApplyDNNVariations). Before that fix (dnn_vbf_weighted, 2026-09-17) the DNN was evaluated once, on the nominal inputs, and the shifted histograms used that nominal score: a variation could only move events across the selection, not along the DNN. Events selected only with the shifted jets carry nominal inputs in which the VBF pair does not exist (VBF variables at the default -10000), so they got a score near 0 and piled up in the first DNN bin (JES Down, DY M-50 in the Z sideband: +56% in bin 1, other bins unchanged), while the opposite direction only lowered the normalisation.

    6.6 One-off histograms¶

    ./hmumu hist custom --era 2025 --dataset VBFHto2Mu_M125_powheg \
    --variable DNN_NNOutput --region Signal_Fit --category VBF --one-file --run
./hmumu hist custom --era 2024 --datasets signals,EWK --systematics Central,Muon --condor --run
python3 histograms/hist_maker.py --help              # every producer option

    7. Datacards¶

    7.1 DNN card (H→μμ)¶

    IN=$HMUMU_HISTOGRAMS/dnn_vbf_eta_regions_syst/Hists_systMerged
python3 combine/build_signal_extended_datacards.py --input $IN --allow-unmerged \
    --eras 2022,2022EE,2023,2023BPix,2024,2025,2026 \
    --eta-categories incl --dy-model lnn --channels sr,hsb --blind-split 0.8 \
    --output combine/results_X/lnn/datacard.txt
# the same through the CLI:
./hmumu combine cards --input $IN --allow-unmerged --eras 2024 --eta-categories incl \
    --dy-model lnn --output combine/results_X/lnn/datacard.txt
    option values
    --input Hists_systMerged of the campaign (default: dnn_vbf_weighted, change it)
    --eras default every era with a merge receipt
    --channels sr (Signal_Fit_VBF), hsb (H_sideband_VBF), zsb (Z_sideband_VBF); e.g. sr,hsb
    --eta-categories incl (whole VBF) or CC,CF,FF (one channel and one DY normalisation per category)
    --dy-model lnn, rateparam-pu, rateparam-both, inclusive (below)
    --blind-split 0.8 SR split at DNN 0.8 into ..srlo/..srhi, so a data fit can mask the high part
    --dy-scale-shape-only DY QCD scales shape-only + QCD_{fac,ren}_scale_V_DYextrap lnN for the Z-sideband → channel extrapolation (templates in patched_templates/)
    --rateparam-scope group\|all one DY rateParam per era group or one for all eras
    --rate-param-range 0.2,5 rateParam range
    --xsec-model per-source\|per-process cross-section lnN (7.3); default per-source
    --variable default DNN_NNOutput
    --allow-unmerged accept eras without merge receipt (only after check_templates --stage merged OK)

    Channels are named y<era>_<region>[<eta cat>], e.g. y2024_srlo, y2024_srhi, y2024_hsb, y2024_srCC.

    DY models

    model DY PU1 + PU2 DY Hard
    lnn DYVBFZ_fit_2JPU1/2_<group> lnN DYVBFZ_fit_2JHard_<group> lnN
    rateparam-pu one free DY_norm_PU_<group> lnN
    rateparam-both DY_norm_PU_<group> DY_norm_Hard_<group>
    inclusive one DY template (DYto2Mu_MLL105To160), one free rateParam –

    The lnN are 1 + error/value of the VBF components of the 012J fit (reweights/dy_012j_reweight_skim_v4/<group>/dy_012j_reweight_fit.json), per group 2022_2022EE, 2023_2023BPix, 2024, 2025, 2026. inclusive cannot take --dy-scale-shape-only.

    What is in the card

    • shape nuisances from config/<era>/systematics.yaml (JES 11 sources, JER 6 η/pT bins, muon ID/iso/trigger, muon scale/resolution, PU, QCD scales, PDF, EWK Z parton shower). A shape column is enabled only where both variations exist, are positive and have no negative bin; the build log lists the disabled ones. CMS_scale_j_total_<era> is dropped (the regrouped sources are used);
    • luminosity (datacard_inputs.lumidict; 2026 uses the 2025 values);
    • cross sections (7.3), DY lnN or rateParams (above);
    • parton shower of EWK Z and VBF H (derived_systematics): herwig ± 0.5·|pythia − herwig|; VBF H reads VBFHto2Mu_M125_powheg_herwig where it exists (2024–2026), and in 2022–2023 gets the 2024 difference scaled by lumi(era)/lumi(2024) (CMS_hmm_VBFH_partonShower, one nuisance for all eras);
    • autoMCStats (Barlow–Beeston lite);
    • a process absent in an era (e.g. SingleH) is skipped.

    7.2 VBF-selector cards (EWK Z in the sidebands)¶

    Written by studies/vbf_selector/fit_ewkz_systematics.py, which also runs the fits (section 8.6). One card per fit: all, Z_sideband, H_sideband, <era>, <era>_Z, <era>_H, in combine/results_vbf_selector_ewkz_syst/<no_shape_systematics|systematics>/<dy model>/datacard_<fit>.txt. DY models: single (one DY template, free per channel), hard-pu (DY Hard and DY PU free per channel), hard-pu-lnn (constrained by the 012J fit); run_fit_ewkz_pu_split.py adds hard-pu1-pu2 (diagnostic). POI: the EWK Z signal strength.

    7.3 Normalisations of the merged processes¶

    Every background except DY is a sum of datasets (TT = 3, ST = 6, TW = 6, VV = 10, VVV = 4, W = 3, TTX = 4, SingleH = 6, ...). --xsec-model per-source (default, shared with the VBF selector in combine/xsec_normalisation.py) gives each process one lnN per cross-section source (xsec_TT, xsec_tW, xsec_ST_t, xsec_ST_s, xsec_WW, xsec_WZ, xsec_ZZ, xsec_ggH, xsec_qqH, ...):

    kappa = 1 ± Σ_i f_i δ_i

    with f_i the yield fraction of dataset i in the channel (read from <campaign>/Central/Run3_<era>/<dataset>.root) and δ_i its relative uncertainty in config/crossSections13p6TeV.yaml. The same source is the same nuisance in every process and era.

    Why not one column per dataset: for a normalisation (lnN) the weighted kappa is the same constraint, while splitting the templates gives tens of low-statistics columns (each with autoMCStats, empty bins and its own shape nuisances) and a much slower fit. Separate columns are worth it only if a dataset needs its own shape treatment.

    The build log ([XSEC] lines) lists what is missing in the yaml; fix it there, and add an alias in XSEC_ALIASES of combine/xsec_normalisation.py when the yaml key differs from the dataset name. Gaps on 2026-10-06:

    process in crossSections13p6TeV.yaml
    W (WtoMuNu, WtoTauNu) no uncertainty
    VV, VVV, TTX generator integration error only
    EWK Z integration error only (±0.5%): to be replaced by the sideband measurement (ewkz_fit_motivation.md)

    8. Fits¶

    Combine runs from the container: always through run_combine_tool (or the scripts below, which use it).

    8.1 Pre-fit Asimov, toysFreq Asimov, data¶

    mode what when
    asimov -t -1 --expectSignal 1: expected yields with r = 1, nuisances at nominal expected sensitivity of the model as simulated
    toysfreq Asimov built after fitting the nuisances to the data with r = 1 expected sensitivity once the model is adjusted to the data
    data the observed data sidebands; DNN SR only below 0.8 and only background-only

    Blinding. The DNN SR above 0.8 is never looked at. The one-line --toysFreq fits the nuisances to every channel, SR above 0.8 included, MC-statistics parameters too (the old +7.7% of CC/CF/FF came from that). Use fit_suite.py --mode toysfreq --freq-mask '_srhi$' (two steps: a data fit with the high SR masked, then the Asimov from that snapshot) or the pre-fit Asimov (SE_SIG_OPTS=""). Data fits of the DNN card: background-only, high SR masked (--mask '_srhi$' --data-bonly), or the whole SR masked.

nohup ./hmumu chain all > chain.log 2>&1 &
./hmumu chain dnn-vbf --eras 2024,2025    # one stage

    status follows skim → manifest → DY payloads → Central → syst → hadd → merge-syst with the same functions as the campaign engine, and flags STALE products (older than an input). With --campaign and --eras it takes seconds instead of minutes.

    chain stage runs
    dy-weights validate, then dy-weights run until the three payloads are done
    all-variables hist all_variables: submit, hadd, merge-syst, plot
    dnn-vbf the same for hist dnn_vbf
    vbf-eta hist vbf_eta_regions, hist dnn_vbf_eta_regions

    14. Traps and troubleshooting¶

    symptom cause and fix
    hadd writes broken files, merged templates at ~50% of nominal a raw file truncated by EOS, or a stale hadd that lost a dataset: check_templates.py --stage raw --quarantine, resubmit, redo hadd and merge
    check --check-level root never ends uproot hangs on a truncated file over EOS FUSE: use check_templates.py
    hadd/merge-syst refuse to run datasets that cannot be produced (FlashSim in DNN campaigns, herwig without manifest): direct commands, 6.3
    builder refuses an era no merge receipt: merge-syst, or --allow-unmerged after the merged check
    DY histograms STALE DY weights refitted: resubmit DY with --force (section 5)
    jobs held/removed after 8 h +JobFlavour = "tomorrow", MaxRuntime 86400, or hmumu shard
    use of undeclared identifier 'genWeight' empty skim dataset (Run3_2022/ZZto2Nu2Q_powheg, ...): exclude it
    OOM on lxplus tools reading the skims with AsNumpy: one era, --threads ≤ 4, --roc-max-files
    Unable to remove file for truncation on EOS file owned by another user: write elsewhere
    toysFreq significance higher than expected the nuisances were fitted to the blinded SR: --freq-mask '_srhi$' or SE_SIG_OPTS=""
    stat-only fit fails --robustFit with only r floating, or r < 0: fit_suite.py handles it (no robustFit, rMin 0)
    FitDiagnostics --saveWithUncertainties takes hours use fit_shapes.py (8.3)
    JES/JER templates pile into the first DNN bin dnn_vbf_weighted: use dnn_vbf_eta_regions_syst
    options changed on an existing output root timestamps do not record options: new --output-dir or --force
    editing code while jobs run Condor jobs read the checkout live: do not edit or move files while a campaign of that checkout runs
    zsh set -- $var does not split words write multi-step loops as bash scripts
